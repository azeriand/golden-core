# golden-core

Event media gallery built with Next.js 16 (App Router) and Postgres. Guests log
in, upload photos/videos to a shared event, and the media is auto-categorized
into time-based sections. Media is stored in Vercel Blob; video posters are
generated by a separate worker service.

## Stack

- Next.js 16 (App Router, Turbopack) + React 19
- Postgres (via `pg`)
- Vercel Blob for media storage
- JWT auth in an httpOnly cookie
- A separate poster worker in `worker/` (deployed to Railway)

## Requirements

- Node.js `20.20.0` (see `.nvmrc`)
- Yarn (Yarn Classic `1.22.x`; the repo uses a single `yarn.lock`)
- A Postgres database
- A Vercel Blob store

## Getting started

```bash
yarn install
yarn dev
```

Open http://localhost:3000.

> Note on uploads in local dev: the direct-to-Blob webhook (`onUploadCompleted`)
> does not fire against `localhost`. The client `confirm` route is the reliable
> source of truth locally, so uploads still work — the webhook is only a
> production reconciliation path.

## Environment variables

Create a `.env.local` (git-ignored). These are the variables the app actually
reads.

### Required

| Variable | Purpose |
| --- | --- |
| `JWT_SECRET` | Secret used to sign/verify auth JWTs (HS256). Use a long random value. |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob token. Stays server-side (never sent to the client). |

### Database (choose ONE of the two options)

Option A — a single connection string:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Postgres connection string. (`DB_DATABASE_URL` / `DB_POSTGRES_URL` are also accepted as fallbacks.) |

Option B — individual fields (Neon/Vercel integration style):

| Variable | Purpose |
| --- | --- |
| `DB_PGHOST` / `DB_POSTGRES_HOST` | Host |
| `DB_PGDATABASE` / `DB_POSTGRES_DATABASE` | Database name |
| `DB_PGUSER` / `DB_POSTGRES_USER` | User |
| `DB_PGPASSWORD` / `DB_POSTGRES_PASSWORD` | Password |

### Database TLS (recommended for production)

By default the DB connection does NOT validate the server certificate (kept for
compatibility with existing setups). Harden it in production with ONE of:

| Variable | Purpose |
| --- | --- |
| `DB_SSL_CA` | The provider's CA certificate (PEM). When set, the certificate is validated (`rejectUnauthorized: true`). |
| `DB_SSL_REJECT_UNAUTHORIZED` | Set to `true` to validate against the system trust store (no custom CA). |

### Optional / feature flags

| Variable | Purpose |
| --- | --- |
| `ENABLE_USER_ADMIN_API` | Set to `true` to enable the admin `PUT /api/me` user-management endpoint. It is DISABLED (503) by default because there is no management UI yet. |
| `NODE_ENV` | `production` makes the auth cookie `secure`. Set by the platform. |

## Database setup

The schema lives in `schema.sql`; incremental changes are in `migrations/`.

```bash
# Base schema
psql "$DATABASE_URL" -f schema.sql

# Migrations, in order
psql "$DATABASE_URL" -f migrations/001_add_media_type_column.sql
psql "$DATABASE_URL" -f migrations/002_add_upload_id_column.sql
psql "$DATABASE_URL" -f migrations/003_media_section_id_nullable.sql
psql "$DATABASE_URL" -f migrations/004_add_poster_url_and_poster_jobs.sql
# (add-blurhash-column.sql adds the blurhash column if not already present)
```

### Demo user (optional)

The demo auto-login (`POST /api/demo/auth`) expects a user with email
`demo@golden-core.app` to exist. Create one if you want the demo flow to work.

## Poster worker (`worker/`)

A separate long-running service that polls the `poster_jobs` queue, extracts a
video frame with ffmpeg, uploads a poster to Vercel Blob, and records
`media.poster_url`. It is deployed to Railway (`worker/railway.json`), NOT on the
Vercel serverless path. It needs `DATABASE_URL` and `BLOB_READ_WRITE_TOKEN`. See
`worker/package.json` for its scripts (`build`, `start`, `backfill`).

## Build & deploy

```bash
yarn build
yarn start
```

The app targets Vercel. Set the environment variables above in the Vercel
project settings. The `.env.local` file is only for local development.

## Security notes

- Auth is a JWT (HS256) stored in an httpOnly, `sameSite=lax` cookie; it is
  `secure` in production.
- `proxy.ts` is a Next.js Proxy (the renamed "middleware") that rejects requests
  without an `auth_token` cookie on `/api/event/*`. Full JWT verification still
  happens per-route.
- See `docs/plan-correcciones-produccion.md` for the production-hardening plan,
  including items still open (e.g. a Content-Security-Policy and a distributed
  login rate limiter for serverless).
